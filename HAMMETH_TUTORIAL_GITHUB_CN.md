# Tutorial: Run `hammeth` on the tutorial scWGBS dataset

The `hammeth` workflow has three core steps:

1. `prepare`: convert indexed BAM files into chromosome-wise PAT files
2. `hamdist`: sample PAT files, calculate local Hamming-distance-based variability, and select the most informative genomic bins
3. `matrix`: quantify methylation states in the selected regions and build the final cell-by-cell Hamming distance matrix

The tutorial below explains the principle of each step, the command to run, the most important parameters, and the files generated by each step.

## Usage principles

`hammeth` is a command-line toolkit for single-cell whole-genome bisulfite sequencing (scWGBS) analysis. The central idea is:

1. represent per-cell methylation reads as compact PAT strings
2. use Hamming distance between local methylation patterns to score genomic bins
3. keep the most variable bins and use them to construct a robust cell-by-cell distance matrix

Compared with directly using all CpG sites genome-wide, this design focuses the downstream analysis on loci that are informative for cell-state or cell-type differences.

## What you need

Before running the tutorial, prepare the following files:

1. A folder of indexed deduplicated BAM files, one BAM per cell.
2. A chromosome-level region directory.
3. A chromosome-level CpG reference directory.
4. A metadata table that maps cell IDs to cell types.

In this tutorial, the example inputs are:

```text
tutorial_bam/
  SRR13751331_dedup.bam
  SRR13751331_dedup.bam.bai

```

The current implementation also assumes that the following tools are available in your environment:

```text

```

If you install `hammeth` as a package, you can use the `hammeth` command directly. If you are working from source, you can also run the CLI entry point with Python.

## Step 1. Prepare BAM files into PAT files

### Principle

`hammeth prepare` converts each cell’s BAM file into chromosome-wise PAT files. A PAT record stores:

1. the chromosome
2. the starting CpG index of a methylation pattern
3. the methylation pattern itself, encoded as a CpG string
4. the count of identical observations

This step is important because the downstream Hamming-distance calculation does not work directly on BAM alignments. Instead, it works on compact methylation patterns aligned to CpG indices.

Conceptually, this step does three things:

1. read each BAM file chromosome by chromosome
2. extract CpG-resolved methylation patterns from each read
3. write one compressed PAT file per cell per chromosome

After `prepare` is finished, all later steps work on the PAT files rather than on the raw BAM files.

### Command

```powershell
hammeth prepare `
  -i tutorial_bam `
  -o tutorial_run/pat `
  -m 4 `
  -r human_hg38_region `
  -cp human_CpG_hg38 `
  -g hg38 `
  -cl chr1 chr2 chr3 chr4 chr5 chr6 chr7 chr8 chr9 chr10 chr11 chr12 chr13 chr14 chr15 chr16 chr17 chr18 chr19 chr20 chr21 chr22 chrX chrY
```

If you are running from source:

```powershell
py -m hammeth.cli prepare `
  -i tutorial_bam `
  -o tutorial_run/pat `
  -m 4 `
  -r human_hg38_region `
  -cp human_CpG_hg38 `
  -g hg38 `
  -cl chr1 chr2 chr3 chr4 chr5 chr6 chr7 chr8 chr9 chr10 chr11 chr12 chr13 chr14 chr15 chr16 chr17 chr18 chr19 chr20 chr21 chr22 chrX chrY
```

### Key parameters

| Parameter | Meaning | Recommended value in this tutorial |
|---|---|---|
| `-i` | input BAM directory | `tutorial_bam` |
| `-o` | output PAT directory | `tutorial_run/pat` |
| `-m` | number of worker processes | `4` |
| `-r` | directory containing chromosome-wide region BED files | `human_hg38_region` |
| `-cp` | directory containing chromosome-wise CpG reference files | `human_CpG_hg38` |
| `-g` | genome label used by the upstream conversion tools | `hg38` |
| `-cl` | chromosome list to process | all autosomes + `chrX chrY` |

### What you should expect after Step 1

After `prepare`, you should have a PAT representation of all cells and chromosomes. This is the input for the Hamming-distance-based region selection in Step 2.

## Step 2. Use Hamming distance to discover informative genomic bins

### Principle

`hammeth hamdist` is the core step of the workflow. It uses local methylation-pattern disagreement to identify bins that are informative across cells.

The procedure can be summarized as:

1. sample groups of PAT files from the cell population
2. merge the sampled PAT files within each chromosome
3. calculate per-bin Hamming-distance metrics inside each merged sample
4. summarize these per-bin metrics across repeated batches
5. rank bins by variability and keep the top bins

This step is not simply measuring mean methylation. It measures pattern-level discordance. Two regions with similar mean methylation can still have very different read-level methylation patterns. Hamming-distance-based scoring is designed to capture this additional structure.

### Command

In this tutorial we use the parameters you specified:

```powershell
hammeth hamdist `
  -i tutorial_run/pat `
  -o tutorial_run `
  -bs 30 `
  -bn 10 `
  -m 4 `
  -n 20000 `
  -r human_hg38_region `
  -cp human_CpG_hg38 `
  -g hg38 `
  -cl chr1 chr2 chr3 chr4 chr5 chr6 chr7 chr8 chr9 chr10 chr11 chr12 chr13 chr14 chr15 chr16 chr17 chr18 chr19 chr20 chr21 chr22 chrX chrY `
  -v hmtop `
  --binsize 5000 `
  --seed 42 `
  --min_hm_count 5 `
  --min_cpg 2 `
  --max_dis 600 `
  --max_possible_read 3000
```

If you are running from source:

```powershell

  --min_cpg 2 `
```

### Key parameters

| Parameter | Meaning | Recommended value in this tutorial |
|---|---|---|
| `-i` | PAT directory from Step 1 | `tutorial_run/pat` |
| `-o` | output root directory | `tutorial_run` |
| `-bs` | batch size, i.e. number of cells sampled per batch | `30` |
| `-bn` | number of repeated batches | `10` |
| `-m` | number of workers | `4` |
| `-n` | number of top bins to keep for downstream analysis | `20000` |
| `-v` | bin selection mode | `hmtop` |
| `--binsize` | genomic bin size in base pairs | `5000` |
| `--seed` | random seed for reproducible sampling | `42` |
| `--min_hm_count` | minimum valid Hamming comparisons required for a bin to contribute to the summary | `5` |
| `--min_cpg` | minimum number of CpGs needed in a bin before it is evaluated | `2` |
| `--max_dis` | maximum read extension distance used in local pattern extraction | `600` |
| `--max_possible_read` | cap on the number of reads considered per bin | `3000` |

### How to interpret `batch size` and `batch number`

These two parameters control the repeated subsampling strategy:

1. `-bs 30` means that each batch is built from 30 cells sampled from the PAT pool.
2. `-bn 10` means that this subsampling is repeated 10 times.

This repeated resampling helps estimate how stable and variable each genomic bin is across the cell population. A bin that repeatedly shows strong Hamming-distance variation across batches is more likely to be informative for downstream analysis.

| File or directory | Meaning |

### What you should expect after Step 2

At the end of `hamdist`, you no longer need the full genome for downstream cell-to-cell comparison. Instead, you now have a focused set of top bins and their CpG coordinates. These selected loci are the regions that will drive the final matrix in Step 3.

## Step 3. Build the final Hamming distance matrix

### Principle

`hammeth matrix` builds the final cell-by-cell distance matrix using the bins selected in Step 2.

The logic is:

1. quantify methylation at CpG sites inside the selected bins for every cell
2. convert these measurements into per-cell binary methylation states
3. align all cells on the same selected CpG positions
4. calculate pairwise Hamming distance between every cell pair
5. export both a long table and a square matrix

This matrix is the main output for downstream visualization and clustering. In the current tutorial, it is later used to draw a heatmap.

### Command

```powershell
hammeth matrix `
  -i tutorial_run/bed `
  -r tutorial_run/middle_res/diff_result/SD_hmtop20000.bed `
  -t tutorial_run/matrix/tmp `
  -ol tutorial_run/matrix/tutorial_hamming_distance_long.tsv `
  -om tutorial_run/matrix/tutorial_hamming_distance_matrix.tsv `
  -mm tutorial_run/matrix/X_memmap.dat `
  -p 4 `
  -b 5000 `
  --overwrite
```

If you are running from source:

```powershell
py -m hammeth.cli matrix `
  -i tutorial_run/bed `
  -r tutorial_run/middle_res/diff_result/SD_hmtop20000.bed `
  -t tutorial_run/matrix/tmp `
  -ol tutorial_run/matrix/tutorial_hamming_distance_long.tsv `
  -om tutorial_run/matrix/tutorial_hamming_distance_matrix.tsv `
  -mm tutorial_run/matrix/X_memmap.dat `
  -p 4 `
  -b 5000 `
  --overwrite
```

### Key parameters

| Parameter | Meaning | Recommended value in this tutorial |
|---|---|---|
| `-i` | per-cell bed directory from Step 2 | `tutorial_run/bed` |
| `-r` | selected-region BED file from Step 2 | `tutorial_run/middle_res/diff_result/SD_hmtop20000.bed` |
| `-t` | temporary directory used during matrix construction | `tutorial_run/matrix/tmp` |
| `-ol` | long-format output table | `tutorial_run/matrix/tutorial_hamming_distance_long.tsv` |
| `-om` | square matrix output file | `tutorial_run/matrix/tutorial_hamming_distance_matrix.tsv` |
| `-mm` | temporary memory-mapped file | `tutorial_run/matrix/X_memmap.dat` |
| `-p` | number of workers for pairwise comparisons | `4` |
| `-b` | number of cell pairs processed per batch | `5000` |
| `--overwrite` | overwrite old intermediate and output files | enabled |

### Result files

The final outputs are:

```text
tutorial_run/matrix/
├─ tutorial_hamming_distance_long.tsv
├─ tutorial_hamming_distance_matrix.tsv
├─ X_memmap.dat
└─ tmp/
   └─ *_VMR.bed
```

### What each file means

| File | Meaning |
|---|---|
| `tutorial_hamming_distance_long.tsv` | pairwise distances in long format, one line per cell pair |
| `tutorial_hamming_distance_matrix.tsv` | symmetric square matrix for clustering and heatmap plotting |
| `X_memmap.dat` | temporary memory-mapped file used during matrix construction |
| `tmp/*_VMR.bed` | temporary per-cell CpG subsets restricted to the selected bins |

### What you should expect after Step 3

At the end of this step, you have the main downstream analysis input:

1. a cell-by-cell Hamming distance matrix
2. a long-format pairwise distance table

These files can be used for:

1. heatmap visualization
2. hierarchical clustering
3. graph-based analysis
4. dimensionality reduction after suitable transformation
